# Workspace private Research authority: candidate handoff

This source extends PR 16 in the existing coordinated release. It does not certify deployment.

Run `python -m app.migrate_security` with backend on PYTHONPATH only after a populated backup/restore has passed. Migration 051 is additive, checksum recorded, advisory locked and idempotent; production schema downgrade is not an automatic rollback strategy. Enforced startup requires the migration ledger and revocation table. Durable cookie revocation affects central session decoding. All deployed custom login, reporting and logout consumers still require acceptance against the exact deployed image.

Run the isolated authority as `uvicorn app.research_introspection_entry:app --host 0.0.0.0 --port 8011` in a separate container with no published host port, attached only to a dedicated internal bridge shared with the Research API. Public app.main does not mount it. The service must load the existing Workspace session authority and database, enforce session_revocation_enforced, and load a new purpose-specific service credential through research_introspection_token_file. The key must not equal the legacy Workspace service token; never share the cookie signing key with Research. Never send keys through chat or commit them.

Only POST /internal/v1/workspace/session/introspect is routed; JSON body is limited to 12KiB, opaque token to 8192 characters, extra claims rejected and responses no-store. Verification fails closed on invalid/revoked/expired cookies, unavailable revocation store, missing authority schema or service authentication failure. The verified subject selects ProjectHead's persisted composite ownership key. Return only project IDs, never project content or a client-supplied owner scope. Research must bind the returned issuer/subject/source project and recheck current grants on each request. The service returns up to 100 current projects; larger portfolios require a per-project contract extension before enabling them in Research.

Reproduce focused tests using Python 3.12 and backend requirements plus pytest, with PYTHONPATH=backend. The isolated-security workflow provides synthetic PostgreSQL tests, including migration idempotence. Synthetic login/session tests do not replace real-account acceptance. Full Workspace regression also needs backend/neural-runtime's PyTorch dependency; its absence produced nine collection errors on the Pi. Do not hide those errors by declaring a focused run a full-suite pass.

Before production: preserve current deployed image and custom overlays, back up the shared Workspace volume and database, prove populated restoration, audit every deployed session consumer, establish private networking and least-privilege service grants, run full regression and valid existing-account login/logout/original-cookie replay, CSRF, cross-owner, persistence and outage tests on isolated staging. Only then may the coordinated release proceed. No current production service is changed by committing this source. Independent maintainers can continue through this PR, the CI workflow and the Research release runbook without Codex.
