# RD-01.4 — Wexford multi-publication research project requirement
**Status:** product requirement and acceptance specification; **not evidence that native authoring/persistence is deployed**.
**Date:** 2026-11-03
**Project:** Wexford Enhanced Rock Weathering (one authenticated owner-scoped research project)

## Decision
A single Wexford ERW research project owns **two independent publication records**:
1. Assignment 1 — Scientific Research Report. Preserve the exact submitted artifact and its feedback as unalterable historical source assets. Create separate editable working revisions for the expanded scientific report, equations, graphs and notebook.
2. Assignment 2 — Evidence-Based Policy Brief. Create and edit a separate 2–3-page policy-brief publication with FIG-PB01 and FIG-PB02; FIG-GEO01 remains review-only unless explicitly cleared.

Do not use two separate projects, overwrite the historic Wexford recovery inventory, collapse the policy brief into the scientific report, or link the Metrics project to Wexford. The previously proposed narrow title "Wexford ERW — Policy Brief & Publication" should be interpreted as the Wexford research project's publication workspace, not permission to exclude Assignment 1.

## Required data separation
- Project: server-generated ID, owner identity, project title, creation timestamps.
- Publication: server-generated ID, parent project ID, document kind (`scientific-report` or `policy-brief`), title, workflow status, source citations, figure references.
- Revision: publication ID, monotonically increasing revision, content and/or immutable artifact digest, revision timestamps, author and notes.
- Historical submission: immutable artifact bytes, checksum, original filename, submission date if evidenced, relation to Assignment 1. Never silently replace with a revision.
- Figure: stable figure ID, content hash, source material, review status and inclusion status per publication.
- Research objects: owner-scoped reusable evidence, data, calculations, literature and geospatial context, linked by IDs; no duplicate required uploads.

## Workflow acceptance
1. With existing Workspace login, create one `Wexford Enhanced Rock Weathering` project without altering Metrics of Sustainable Development.
2. Create independent scientific-report and policy-brief publication entries in the Wexford project.
3. Upload original Assignment 1 as its own immutable submitted artifact; preserve feedback; create a separate editable revision.
4. Save scientific manuscript to a second revision, logout/relogin, reopen and verify bytes, text, citations and figures.
5. Create policy brief with FIG-PB01/FIG-PB02 and their provenance; save, logout/relogin and reopen with stable publication ID.
6. Keep FIG-GEO01 marked review-only and prevent publication inclusion until cloud, geography, rights, attribution and editorial checks are complete.
7. Version both publications independently; changing one must not change the other.
8. Export separate DOCX and PDF files; verify pages, figure legibility, source citations, and parity to stored revision.
9. Confirm permissions: owner-only reads and writes; unauthorized project IDs cannot access either report or evidence.
10. Existing project list, Reporting Studio and Private Research catalogue resolve to the same Wexford project; distinct publication records remain visible within it.
11. Ensure the historical Wexford recovery/project inventory is not overwritten or automatically migrated.

## Existing implementation vs missing capability
The historical `app.wxr_private_projects` POST `/v1/private-research/persistent-projects` creates owner-scoped project heads and the route supports file upload for PDF, DOCX and more, with duplicate filenames or SHA blocked rather than replaced. These endpoints **do not themselves implement** publication records, edited document revisions, native figure insertion, or full DOCX/PDF publication authoring. The endpoint is not considered production-ready without authenticated browser verification on deployed runtime.

PB00 therefore reuses the existing project-create route if mounted; RD-01.4 Publication Studio adds **two independent native publication streams** under the same owner-scoped Wexford project. Do not implement a parallel authentication, database or document engine.
