# SC-RUN-VERIFY-01 addendum (2026-11-24, SC-WS-PR-01)

The evidence in this directory (`report.md`, `acceptance.json`, `evidence/`) is the **historical
baseline** for source commit `evidence/source-commit.txt`. It is retained unchanged.

That baseline recorded that a reproduction verification still classified a run pair as `exact`
after the stored output bytes were modified, because reproduction compared registered metadata
only. The corrective change, PR #79 (SC-RUN reproduction integrity), re-reads and hashes the stored
artifact bytes of both runs and classifies the pair `incomplete` when any artifact cannot be
verified. Legacy metadata-only `exact`/`compatible` records are reported as `incomplete` on read.

`backend/tests/test_sc_run_verify01_postgres.py` now asserts the corrected contract:

| Check | Baseline (recorded) | Now asserted |
|---|---|---|
| Intact artifacts: classification | `exact` | `exact` |
| Intact artifacts: `comparisonExecuted` | `false` | `true`, `artifactIntegrity.status = verified` |
| Modified artifact bytes: artifact read | HTTP 503 | HTTP 503 |
| Modified artifact bytes: classification | `exact` | `incomplete`, `artifactIntegrity.status = incomplete` |

Negative control: the updated test fails on `main` without PR #79.
`exact` remains a statement about byte-identical registered outputs, environment and runtime
adapter; it is not a scientific validation (`scientificValidationPerformed = false`).
