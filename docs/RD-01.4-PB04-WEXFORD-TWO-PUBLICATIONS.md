# RD-01.4-PB04 — Wexford Two-Publication Native Workspace Integration

**Release candidate:** 2026-11-03. **Status:** isolated source and tests PASS; Raspberry Pi run PENDING; Contabo staging, source-parity mapping, authenticated browser acceptance and production PENDING. This package DOES NOT update a running service.

## What is built

- Additive FastAPI router `backend/app/rd014_publication_records.py` for TWO independently versioned scientific manuscript streams within ONE owner-scoped existing Private Research project.
- A single same-origin `/v1/private-research/persistent-projects/{project_id}/publications/ui` Markdown editing view, protected by existing signed Workspace session.
- Owner-bound GET list and retrieve, POST create and PUT compare-and-swap update, GET revision history and historical document text.
- Existing `repository.get_project`, `object_store.get_artifact`, `object_store.store_artifact`, `ArtifactRevision`, `ArtifactStoreRequest`, and signed session logic reused. No new project creation, auth service, database schema or storage engine.
- Optional exact-bytes historical Assignment 1 submission DOCX/PDF artifact link, original ID/hash/revision pinned and cannot be changed through this API.
- Figure links use owner-project-scoped artifact IDs and SHA-256. Exports require metadata-based reviewed science and rights; **FIG-GEO01 always disallowed for embedding in this candidate** pending SCL/geographic/license acceptance. Editorial metadata alone is NOT an independent audit.
- Source/figure references retained across text edits unless explicitly replaced; no delete endpoints, no automatic publication or PDF/DOCX export.

## Intended API

| Method | Route | Function |
|---|---|---|
| GET | `/{project_id}/publications/ui` | Owner-only two-document Markdown editor |
| GET | `/{project_id}/publications` | Owner-scoped catalog |
| POST | `/{project_id}/publications/{scientific-report\|policy-brief}` | Create first draft, expectedRevision=0 |
| PUT | `/{project_id}/publications/{scientific-report\|policy-brief}` | Save independent revision with compare-and-swap |
| GET | `/{project_id}/publications/{kind}` | Read current saved Markdown |
| GET | `/{project_id}/publications/{kind}/revisions` | List revision hashes |
| GET | `/{project_id}/publications/{kind}/revisions/{revision}` | Reopen immutable historical revision |

All paths have the existing prefix `/v1/private-research/persistent-projects`.

## Source-parity and release restrictions

The default GitHub Workspace main branch does not contain the already-deployed `app.wxr_private_projects` module, despite observed module presence in the live container. The running Contabo `app.main`/Repository/Session/Reporting Studio code must be reconciled before mounting this router. Do not blindly patch main.py from GitHub; the validated integration requires matching the deployed overlay fingerprints.

To prepare a *source candidate* against the reconciled existing main.py, add exactly once:

```python
from .rd014_publication_records import router as rd014_publication_records_router
app.include_router(rd014_publication_records_router)
```

Place the import with existing router imports and the include with existing router registrations. **Do not execute against production before staging/backup/rollback acceptance.** Prior to activation check route collisions and ensure the two publication record endpoints are not already provided by the current RD-01.2 editor.

Original source uploads are not made immutable by all possible legacy artifact routes: the new publication API only pins the original ID/hash/revision and detects changes on later saves. A separate storage policy/backup safeguard is required before certifying unalterability. PDF/DOCX authoring/export remains RD-01.2/01.4 Publication Studio integration, not this additive view.
